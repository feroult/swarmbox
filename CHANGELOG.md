# Changelog

All notable changes are listed here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the
project follows [semantic versioning](https://semver.org/).

## [Unreleased]

- Added: repository context for new agent sessions (`sysop.autocontext`, on by default; a toggle in **Settings → Sysop**). An agent in a new worktree no longer needs "understand the repo" first: the sysop listens to `tab.events` and, the first time an agent works in a repository, writes a short digest of it in the background (Claude Code's `DIGEST`: a one-shot haiku call over the file list, the top-level docs, the manifests and the recent commits) to `<state>/sysop/digests/<commit>.md`, shared by the repository's worktrees and carried forward to a new commit with the files changed since (no model call), written again after 6 hours or 40 changed files. The shell function of an agent that declares `CONTEXT_ARGS` (Claude Code: `--append-system-prompt-file`) passes the digest of the commit a session starts on, and nothing when there is none, so a box without the sysop starts its agents as before. `0` writes none and removes them at the next start. `swarmbox-sysop context [DIR]` writes one now. New `agent.conf` keys: `CONTEXT_ARGS`, `DIGEST`, `DIGEST_MODEL`.
- Fixed (security): the sysop knew a permission dialog of an agent only by its words on the screen ("Do you want to", "Esc to cancel"...), the vendor's text, which an update of the agent can change: a key that answers the dialog would then be rated as a plain key, not as the user's decision. A tab whose agent reports `blocked` (OSC 7501) now counts as showing a dialog too, also when it turns blocked while an action waits for its countdown or approval; the words on the screen still count (they also catch a `[Y/n]` prompt of a shell).
- Added: Settings > Addons & System has **Update** and **Remove** next to an installed addon. Update installs a managed addon again (`swarmbox addon install NAME --force`): the newest release of a floating one (`latest`), or the version a newer image names for a pinned one (shown only then); an addon that updates itself has none. Remove deletes the install (`swarmbox addon remove NAME`, never `--purge`): logins and settings stay, running sessions keep running, and it asks for a second click. An install baked into the image cannot be removed there. A failed install, update or remove now shows the command's message instead of an error code. On a narrow screen the badges and buttons of an addon go to their own line.
- Fixed: Settings > Addons & System showed **Install** next to an addon that updates itself (Claude Code, agy) after it was installed: the page looked only for the `current` link of a managed install, which such an addon does not have. It now reads the record `swarmbox addon list` reads (`self/.swarmbox-env`, or `current/.swarmbox-env`) and shows the version the program reports (`CMD --version`, run with a scratch HOME and read again when an update replaces the program) for a floating install (`latest`) instead of `latest`, with an **auto-update** badge for an addon that updates itself (Claude Code, agy); a managed install whose link exists without its record (an install that did not finish) shows Install again, as `swarmbox addon list` says it needs a reinstall.
- Fixed: `swarmbox tabs list` named the program a terminal started with as its command (`bash` for an agent the Web Studio started), not the one running in it: herdr-core's list carries no foreground program. It now takes the foreground from the details it already reads for the labels, so an agent that has not reported its state yet (Claude Code on its first screen) counts as an agent in `swarmbox state` and the worktree check, and a tab whose agent exited counts as a shell. Its rows also carry the whole status an agent reports (its `app` too), which herdr-core's list gives only as a word: the sysop no longer rates a prompt to an agent that reports its state as one whose state it cannot read.
- Added: the `codex` addon, OpenAI's Codex CLI (`swarmbox addon install codex`, or `--with codex`): installed with npm on first use, started with `--dangerously-bypass-approvals-and-sandbox` (the box is the sandbox), resumed with `codex resume --last` in the folder of its pin, with its own icon and colour. It is the proof of the agent registry: it is one folder, `container/addons/codex/`, and nothing else in SwarmBox names it. Not measured yet: whether it reports its state (OSC 7501; without it its state is `unknown`), the keys of its permission dialog (the Allow / Cancel card asks you to answer in its terminal), and the box's MCP servers (it gets none).
- Changed: the sysop takes what it needs of an agent from the agent's addon. Where its prompts are kept (the tab naming reads your last requests): a prompt-history JSONL declared in `agent.conf` (`HISTORY`, `HISTORY_FILE`, `HISTORY_FIELDS`: Claude Code, agy) or the addon's own `agent/history.py` (OpenCode's SQLite reader moved there). Its brain and its tab namer: command templates in `agent.conf` (`BRAIN`, `NAMER`, `MODEL`, `NAMER_MODEL`, `LOGIN_HINT`). `sysop.brain` and `sysop.model` default to `auto`: the brain and the model the box's default agent declares, else the first agent that declares one (Claude Code's: the same `claude -p` invocation and `sonnet` as before); `claude` names Claude Code's preset, and any agent's name is accepted by the host. A box with no agent that declares a brain starts the sysop and fails a goal with a clear reason, instead of failing its self-test. Only Claude Code declares a namer and a brain: the one-shot invocations of agy and OpenCode for this are not measured.
- Changed: the box's list of MCP servers belongs to no agent: `swarmbox-mcp` writes it to `<workspace>/.local/share/swarmbox/mcp-servers.json`, and each agent addon gives it to its agent in its own format with an `agent/mcp.sh` that `swarmbox addon prepare` runs at every start (Claude Code: a copy in `~/.claude/mcp-servers.json`, the file its function passes, always present, empty when the box has none; agy: the Antigravity plugin of the box; OpenCode reads it for its configuration). The default settings of an agent are its addon's `agent/settings.json`, seeded once into the file its `SETTINGS_FILE` names by one shared helper (`swarmbox-agents seed`), with the same rules as before (a key you have wins; a default you removed stays removed); the `prepare.sh` of `claude` and `antigravity`, which did only that, are gone.
- Fixed (security): the **Cancel** button of the Web Studio's card for a blocked agent typed `n` and Enter into its dialog, and **Allow** typed `y` and Enter. Claude Code's dialogs are menus: a typed letter does nothing and Enter confirms the highlighted option, so in a permission dialog, where **Yes** is highlighted, Cancel allowed the request (measured with Claude Code 2.1 on its folder-trust dialog). The card now presses the keys the agent declares in its `agent.conf` (`ANSWER_ALLOW`, `ANSWER_DENY`, as keys): `1` (Yes) and Esc for Claude Code. An agent that declares none (agy and OpenCode, whose dialogs are not measured yet) gets nothing typed, and the card says to answer in its terminal.
- Changed: what an agent's screen says (its state when it reports none, its input box, whether a submitted text left it) is read by the screen adapter of its addon (`agent/screen.py`); Claude Code's rules moved there unchanged. An agent without an adapter is in state `unknown` and its submissions are verified by the state it reports, never by Claude Code's rules. `swarmbox tabs send` refuses the reserved prefixes of the agent of the tab (`RESERVED_PREFIXES`, `/` and `!` by default), and so does the sysop's policy, which also rates a prompt to an agent whose state nothing can read as medium (it may answer a dialog). An agent that declares `TERM_IMAGE_PASTE=none` gets no pasted image path.
- Changed: the shell functions of the agents are generated from their `agent.conf` (`swarmbox-agents sh`, evaluated by every shell): the auto-approve words (`YOLO_ARGS`), the words that give the agent the box's MCP servers (`MCP_ARGS`, also with `YOLO=0`), the subcommands passed through untouched (`PASSTHROUGH`) and the one-shot flags that skip the worktree guard (`PRINT_FLAGS`). The `shell.sh` of `claude` and `antigravity` are gone (OpenCode keeps its own, a declaration cannot say where `--auto` is accepted), and so is the hand-written `codex` function. The worktree guard no longer skips Claude Code's flags for every agent.
- Fixed: a pin or a tab that resumed an agent (`--continue`) and saw it fail at once started a new conversation without a word, also when the failure was a login that expired. It now says so in the tab (`[swarmbox] claude --continue ended at once (exit 1): starting a new conversation`).
- Fixed: the Web Studio decided that a terminal was a full-screen program (and held its output after a resize for up to 3.5 s) by names: a tab named like an agent, an agent label left on a shell, or any program that was not a shell (a long `npm test`) got the masks meant for an agent's redraw. The gateway now reads the terminal's own signals: the alternate screen and mouse reporting that the program turns on in its output, and the status an agent reports (OSC 7501); the page no longer sends a guess (`?tui=1`, `tui` in its messages) and gets the gateway's answer instead. The resize and hydration timings of a TUI are a profile that an agent can tune in its `agent.conf` (`TERM_*`), as can the prompt and gutter glyphs of the smart copy.
- Changed: the Web Studio takes the agents from the registry: their names, icons (each agent's `agent/icon.svg`, moved out of the page) and card colours (`COLOR`), the Default Agent choices in Settings, and which tabs are agents. The page loads `/agents.js` before it runs, and `GET /api/agents` and `/agents/<id>/icon.svg` serve the same data. An agent without an icon gets a generic one, and is still shown as an agent (before, an agent without a hand-drawn icon was shown as a shell); the icons of `codex` and `gemini`, which no addon provides, are gone.
- Changed: every part of the box asks the agent registry which programs are agents, instead of its own list (ten lists with different contents before): `swarmbox-tabs`, `swarmbox-state`, the pins, the worktree check, the sysop (its policy, its risk rating, its tab naming, the agents named in its prompt and in the descriptions of its actions), the Web Studio gateway and the terminal cockpit. `codex`, `gemini` and `aider`, which no addon provides, are no longer agents (a CLI installed by hand is a program like any other until an addon declares it); `claude-code` and `antigravity` are recognised everywhere. A tab is detected in one order everywhere: the app it reports (OSC 7501), then its foreground program, then its `swarmbox.agent` label while it does not run a plain shell; never its name.
- Fixed: the default agent was the first addon of `WITH` even when it was no agent (`WITH=gcloud,claude` made `yolo` run gcloud). The host now passes `AGENT` as it is, and the box resolves one default everywhere (`yolo`, New agent, worktree open, the cockpit, the sysop's tab open, pins): `AGENT` when it names an agent, else the first agent of `WITH`, else the first installed agent. `swarmbox tabs open --agent` accepts `yolo` and any name of an agent (`antigravity`), and a pin made with `yolo` stores the agent it runs.
- Added: the agent registry. An addon is a coding agent when it has an `agent/agent.conf` (identity, launch and resume arguments, terminal status source, input semantics, secrets, terminal timings; docs/agents-design.md); `claude`, `antigravity` and `opencode` declare theirs. `swarmbox-agents` (`list`, `get`, `resolve`, `default`, `generate`, `sh`, `check`) reads them, `serve` writes `/tmp/swarmbox/agents.json` at startup (and warns when `AGENT` names no agent), and `swarmbox addon validate` checks the `agent/` folder. One library per language (`swarmbox_agents.py`, `agents.mjs`) gives the same answers, held to the same test vectors.
- Fixed: after a prompt sent to agy or OpenCode, `swarmbox tabs send` (and the Sysop's `run`) reported success without checking it: the check reads the input box, and only Claude Code's is known. For an agent whose box cannot be read, the check now waits for the state the agent reports (OSC 7501) to turn busy or to a dialog; when it does not, the answer carries `"verified": false` (no second Enter, as nothing says the text is still there) and the Sysop is told to read the screen before sending again. A send to Claude Code also answers `"verified": true`.
- Fixed: the Sysop rated reading the login files of the agents as low risk: `~/.claude/.credentials.json`, `~/.claude.json`, `~/.gemini/oauth_creds.json` and `google_accounts.json`, agy's `antigravity-oauth-token` and OpenCode's `auth.json` are now secret files (at least medium, like `~/.ssh`), and naming `GEMINI_API_KEY`, `GOOGLE_API_KEY` or `OPENAI_API_KEY` is treated like naming `ANTHROPIC_API_KEY`.
- Fixed: agy (Antigravity) never had the MCP servers of the box (chrome-devtools), which Claude Code and OpenCode get. The `antigravity` addon now writes them, at every start, as an Antigravity plugin of SwarmBox's own in `~/.gemini/config/plugins/swarmbox/` (`agy plugin list` shows it); your own `~/.gemini/config/mcp_config.json` is not touched, and `agy plugin disable swarmbox` turns it off.
- Fixed: with `YOLO=0` (auto-approve off), `claude` also lost the MCP servers of the box (chrome-devtools): the function passed `--mcp-config` only together with `--dangerously-skip-permissions`. It now passes the MCP servers in both modes.
- Fixed: the default agent was resolved differently in each place. With `AGENT=antigravity` (the addon name of agy, which `yolo` accepts) the Web Studio's New agent started `yolo` under a `yolo` label, worktree open started a plain shell, and the cockpit's new agent tab fell back to `yolo`; and with no default agent, opening a worktree started `claude` even in a box without it. New agent, worktree open, the cockpit, the agent launcher and pins now share one resolution: the agent named (by its command or another name of it), else the box's default agent, else `yolo` for New agent and a shell for worktree open.
- Fixed: Claude Code reports itself as `claude-code` in its terminal status (OSC 7501), a name the terminal cockpit and `swarmbox state` did not know: the cockpit's tab line showed no `claude` badge when the process name did not say it, and `swarmbox state` found the agent only by its command. Both now read `claude-code` as `claude` (and `antigravity` as `agy`, which they already did in part).
- Fixed: an agent tab opened by `swarmbox tabs open` (and so by the Sysop's `tab open`) started the agent without its shell function: `bash -lc "exec claude"` runs the program itself, so Claude Code and agy came up without auto-approve and Claude Code without the box MCP servers (chrome-devtools). The tab now starts the agent through an interactive shell, as the Web Studio and the pins do, and a login shell takes its place when it exits.
- Fixed: the worktree collision check (a second agent on the same repository) now sees an agent tab by its `swarmbox.agent` label while the agent runs, so an agent whose process is not named after it (OpenCode under `node`) is found. The label was compared with `True`, but `swarmbox-tabs list` gives it as a string, so it never counted; a label on a tab that is back at a plain shell still does not.
- Added: zero-dependency, theme-aware syntax highlighting in the Web Studio file viewer (both the slide-over drawer and standalone `/view` tab) for source files, JSON, HTML Source, Markdown Raw, and fenced code blocks inside rendered Markdown documents, with multiline token support and a 250 KB fallback guard.
- Fixed: the Web Studio buttons that hand a prompt to an agent (**Ask to commit**, **Resolve**, **Commit main**, and the agent hand-off of **Test & Push** / **Merge & push**) took seconds to reach it, up to a minute. They used herdr-core's `terminal.send`, which holds a delivery while a person was active in that terminal: about 3 s after a mouse report, which xterm sends as the pointer crosses an agent's terminal on its way to the button, and up to `draft_wait` (60 s) with text in the input box. The gateway now types the prompt straight into the PTY through an attach stream (the one of a browser already on that tab, or a short one at the PTY's current size) and presses Enter as its own write 150 ms later, so it arrives at once (~150 ms). `terminal.send` stays as the fallback when the attach fails. Text already in the agent's input box is not cleared: the prompt is typed after it.
- Fixed: closing an agent tab in a worktree no longer makes the Web Studio sidebar jump (every card slid down and back up). Between the kill and the auto-clean of the empty worktree, the snapshots sent by the herdr-core events listed that worktree as pending for a moment, and the **Pending worktrees** pill, which had no flex `order`, appeared above the agent cards. The worktree of a tab being closed is now held out of the pending list until the cleanup decision, a removed worktree leaves the cached list at once (also on **Merge & close** and remove), and the pill sits at the bottom of the sidebar, after the shells, as its markup intended.
- Fixed: the Sysop's automatic tab naming could give a tab a title without its subject, in English, for a Portuguese request ("entenda o repo e verifique se ... o rex como engine de terminal em vez do herdr" became `Goal: evaluate`). The naming model ignores the 3-word, 18-character limit about one time in three ("Comparar Rex e Herdr como engine de terminal"), and the title was cut from the end, which kept the activity and lost the subject (`Comparar Rex`, `Comparar Rex vs`). Now a label such as `Goal:` or `Título:` is removed, an answer too long for the sidebar loses its leading activity verb (evaluate, comparar, ...) before the cut, a dangling connector (`vs`, `ou`, `como`) is dropped, and an answer that is only an activity counts as KEEP. The prompt now forbids labels and activity words and asks for the language of the requests, with Portuguese examples. The `autoname` log line of a rename also shows the model's raw answer.
- Removed: the standalone `herdr` TUI binary (0.9.5) and `container/config/herdr.toml`. They ran a separate daemon unrelated to `herdr-core`, which the Web Studio, the cockpit, `swarmbox-tabs` and the sysop all use; nothing in the box started it. The box no longer seeds `~/.config/herdr/config.toml`, and changing the theme no longer rewrites it or runs `herdr server reload-config` (the theme stays in `~/.config/swarmbox/herdr-web-theme`). An existing `~/.config/herdr/` is left untouched; delete it if you like.
- Fixed: switching tabs in the Web Studio (Claude Code to agy and back) could paint the agent's reflow without the loader when a second Studio window or device was open. Every window followed the active tab with a viewport claim at its own size, so two windows resized the PTY back and forth on each switch, and the gateway masked the redraw only for the window that asked. Now only the window the user is in (visible and focused) claims a PTY, a background window follows passively and takes the size back when it gets the focus; a PTY resize masks the redraw for every window attached to it (a claim, a resize, an attach that changes the size, a stream that closes); a passive attach joins at the owner's exact size instead of hc's cached one (an attach always applies its size in herdr-core); and each stream's size is refreshed in herdr-core before `focus(true)`, which re-applies a stream's last size.
- Fixed: an agent started in a folder without a Git repository came back as a bare shell after the box restarted. Only agent tabs opened from **New agent** were persisted, and that picker listed repos only, so in any other folder you opened a shell and typed `claude` or `agy`, and the tab was never pinned. Now every agent session persists until its tab is closed, however it started (typed into a shell, a cockpit or Sysop tab, a worktree opened from its badge): the first time the Web Studio sees a terminal without a pin running a known agent, it gives it an `auto` pin, like a New agent tab (`persist: false` opts out).
- Changed: **New agent** (`Alt+A`) picks any folder, not only a repo, without typing: a **Recent** group (folders you launched in, the folders of open tabs, pinned sessions) above a folder browser with a breadcrumb, where a repo shows its branch, a plain folder opens with `›` (entering a folder selects it), and **Use this folder** selects the one you are in. The filter searches recent folders, every discovered repo and the folder shown; Backspace on an empty filter goes up one folder. New `GET /api/dirs?path=` lists the subfolders; `/api/projects` also returns `recent`.
- Changed: the Sysop's automatic tab naming (`sysop.autoname`) names a tab after what you asked, not after the screen: it reads your last requests in that folder from the agent's own prompt history (`~/.claude/history.jsonl`, `~/.gemini/antigravity-cli/history.jsonl`, the OpenCode database; the screen when they cannot be told apart), which is shorter and more specific. Titles are 1–3 words of at most 18 characters, cut on a word boundary. A tab is no longer named once and frozen: it is renamed when the goal becomes clearer or changes (an exploring first request such as "understand the repo" keeps the folder name), about 3 seconds after you send a request (not at the end of a turn that may take minutes; a request cancelled with Esc inside that window is ignored), the same for `claude`, `agy` and `opencode`. A tab that still has no name (its folder or worktree slug) is tried on every new request, with no wait after a `KEEP`; a named tab has a backoff of 3, 10, 30 and then 60 minutes between automatic renames. Every naming decision (the gate that skipped, a `KEEP`, the rename, a failed call, which is retried) is one `autoname <tab>: ...` line in the sysop's `serve.log`. The naming call uses its own short system prompt instead of Claude Code's, with `--tools ""`, no MCP servers and no settings.
- Removed: the `gemini` addon (Google stopped serving Gemini CLI for most accounts; its successor is the `antigravity` addon, `agy`). A `gemini` installed by hand is still recognised as an agent in a tab.
- Removed: the leftovers of the tmux era. The host no longer special-cases the config keys `MUX` and `sysop.panel` (a file that still has one gets the generic "unknown key" warning; `swarmbox config unset KEY` removes it), `swarmbox-attach --web` and the backend function `mux_attach_web` (what ttyd ran; the Web Studio talks to herdr-core itself), and the fallback of a stale `SWARMBOX_MUX=tmux` to herdr. The system section of `swarmbox state` loses its constant `"mux": "herdr"` field.
- Changed: the sysop's MCP action `box_state` always reads the world model from `swarmbox-state` (the checkout's script when it is not on `PATH`), passing it the sysop's own `swarmbox-tabs` command; the ~150-line copy of that logic that only the tests used is gone. A timeout of a child command of the sysop now kills its whole process group, so a `swarmbox-tabs` started by `swarmbox-state` cannot outlive it.
- Fixed: in the Herdr Web Studio on macOS, `Cmd+C` and `Cmd+V` now copy and paste in a terminal like `Ctrl+C` and `Ctrl+V` (smart unwrapping of wrapped lines on copy, clipboard images on paste, `Cmd+Shift+V` as `Ctrl+Shift+V`); before, only `Ctrl` worked. `Cmd+C` with nothing selected sends nothing; `Ctrl+C` stays `^C`.
- Fixed: in the terminal cockpit, two fingers on a trackpad (the wheel) now reach a program that wants them: a program on the alternate screen (Claude Code in fullscreen, vim, less) gets arrow keys, and one that asked for the mouse gets the wheel as a mouse event (SGR, or the classic encoding) in its own cells. Before, the wheel only scrolled the history kept by the cockpit, so those programs did not move. A shell still scrolls its history. The Web Studio is not touched.
- Added: the `claude` addon now seeds the status line of the box (`swarmbox-statusline`) in `~/.claude/settings.json` on the first start (`prepare.sh`), like the `antigravity` addon does for `agy`: once, keeping every key the user already has, mode 600. Remove it from the file and it stays removed.
- Added: **`swarmbox-state` (`swarmbox state`) & Sysop v2 Actions**: unified read-only box world model (`--section workspace|system|all`) grouping running agents and pending worktrees under their repositories alongside shells, parked sessions, installed agents, and system health/resources. Sysop now pre-seeds the workspace state on stdin (saving Turn 1), streamlines its MCP actions from 13 to 9 (`box_state`, `read_tab`, `run`, `input`, `wait`, `tab` with `open`/`focus`/`rename`/`close`/`wake`, `worktree` supporting both live tabs and detached pending worktrees, `say`, `done`), and uses a concise structured system prompt; `swarmbox-tabs` now always attaches and exposes `swarmbox.agent` and supports `--pin-id` on `open`.

- Added: **Persistent Agent Sessions & Manual/Auto Session Naming** (`docs/pins-design.md`): every open agent tab is pinned automatically in `~/.config/swarmbox/pins.json`, so it survives `swarmbox stop`, `reset`, and reboots; closing the tab discards it. Pinned sessions live-follow `cwd` and agent upgrades (never downgrading an agent pin to `shell`) and, by the boot mode in **Settings → SwarmBox**, start again on boot (**Auto-start**, the default) or wait as zero-RAM **`PARKED`** cards with 1-click **Wake** (**Parked**), both through a safe `--continue` wrapper (`claude`, `agy`, `opencode`; `herdr.sh` → `swarmbox-pins restore`). `swarmbox pins` lists, adds and removes pins by hand; a pin added that way stays `PARKED` when its tab closes. Any tab can be renamed inline (double-click, `Alt+R`, or `swarmbox tabs rename`), locking `title_source=user`; when `sysop` is installed (`sysop.autoname=1`), `tab.events` on `swarmbox-bus` wakes a silent auto-namer that gives unnamed tabs concise titles and logs compact inline rename rows in the Sysop visual feed without consuming the 8-goal conversation memory window.
- Added: **Git Worktrees for Multi-Agent Isolation** (`docs/worktrees-design.md`, `swarmbox-worktree`): opening a second agent (or waking a `PARKED` pin) on a Git repository with an active agent detects the working-tree collision and opens a 2-button popover (`New worktree` / `Same folder`, configurable live in **Settings → SwarmBox** as `ask` / `auto` / `off`). Worktrees live under `~/.local/share/swarmbox/worktrees/<repo>/<id>` on named `sb/wt-*` branches from `HEAD`, copy root `.env*` files (`0600`, `<= 64 KiB`, toggleable) and optional `.swarmbox-worktree` entries, dry-run merges in memory via `git merge-tree --write-tree`, offer an adaptive topbar merge popover (1-click clean merge & cleanup, agent commit, or in-worktree conflict resolution), auto-clean empty unpinned worktrees on close while keeping dirty/unmerged ones under **Pending worktrees**, and expose `open_tab(worktree=true)` and `worktree(tab, action)` to Sysop.
- Added: `swarmbox config path` prints where the config file is (also before it exists), and `swarmbox config unset KEY` removes a key from it, so its default (or the environment) applies again: the comments and the other lines are kept, the file stays mode 600, and it also cleans up a key the file holds that SwarmBox does not know (a typo, or the removed `MUX` and `sysop.panel`, whose warnings now name the command). The README no longer suggests `config set MUX herdr`.
- Changed: on mobile the Sysop sheet opens above the dock bar, which stays as it is (the Sysop capsule and the purple Speak; recording turns it into the voice bar in place), and the sheet opens by itself when a goal is sent by voice or text, so the reply shows in full. Typing is a quiet "Type a message" row at the end of the conversation: tapped, it becomes a one-line field with a round send arrow (16 px, so iOS does not zoom); sent, emptied or closed, it goes back to the row. The big composer with its own Speak and Send is desktop only.
- Changed: the Sysop header keeps **Collapse** apart from **New** and **Stop**: a thin divider and a wider gap sit between them (no divider when neither shows), **New** gets a `+` icon, and on mobile the collapse button is a 34 px target.
- Fixed: the terminal scrollbar of the Herdr Web Studio was always on in an AGY tab (AGY draws inline, so the normal buffer keeps scrollback; a short transcript gave a near-full thumb that looked like a stray line) and never there in a Claude Code tab (it draws in the alternate screen, which has no scrollback). The scrollbar is now an overlay: its thumb shows while you look back through history, for a moment after you scroll (wheel or finger), and while the mouse is at the right edge to grab it; at the live bottom it is hidden, so both agents rest the same.
- Fixed: dragging a terminal of the Herdr Web Studio with a finger moved in whole-row jumps (xterm scrolls by rows); the normal buffer now follows the finger pixel by pixel (whole rows through `scrollToLine`, the rest as a transform of `.xterm-screen` painted with the new rows), moves are coalesced to one per frame, the flick speed is measured over the last 100 ms of the drag, and the text comes to rest on a row, forward in the direction of the glide. The alternate screen (vim, less, TUIs) still gets wheel steps.
- Changed: the Sysop's default autonomy is the new level **`full-auto`**: what you ask, it does, with no approval or countdown for any action (the risk is still rated and written in the log and the audit, and a blocked action, such as control characters or a `/` command for an agent, is still refused). - When the box is running but never writes its readiness marker, `swarmbox` now prints the last 15 lines of the box's log before it exits with status 6, so the cause is on screen.
- The cause of the unwritable folder after a reboot is not known; if the nested Podman service still does not start after this fix, send `podman-service.log`.

## [2.0.0] - 2026-11-11

First stable version. Same feature set as the two prereleases (below), with these changes since 2.0.0-beta.2:

- The README now walks through the install from zero with Claude Code (Podman, the installer, the login, the first run) and through remote access to the same tmux session (from a browser with Cloudflare, or over SSH to your machine).
- The image is published at `ghcr.io/feroult/swarmbox` with the tags `2.0.0`, `2.0` and `latest`; `swarmbox update` follows the `2.0` series.

### Features

- One persistent rootless Podman box per workspace; every terminal tab and the browser join the same tmux session.
- A small neutral image (`node:24-trixie-slim`, user `agent`, about 1.75 GB) with no agent inside. Claude Code, Gemini CLI, OpenCode, gcloud, clasp, Go and Poetry
  install on first use from manifests, through shims, with pinned versions and checksums where the vendor publishes them.
- The workspace is one folder of your machine and holds projects, logins, the SSH key and installed tools; the box can be recreated without loss (`swarmbox reset`).
- One executable POSIX `sh` script, `swarmbox`, on the `PATH` (no shell function, no startup file): `up`, `stop`, `reset`, `url`, `update`, `config`, `env`, `pubkey`, `tool`, `remote`, `fingerprint`, `version`; any other word runs in the box.
- Two ways to install it, with the same result: `podman run --rm IMAGE install [--with TOOLS] | sh`, and `install.sh`, which downloads `swarmbox` from a release and checks its sha256. The release attaches `swarmbox`, `swarmbox.sha256` and `install.sh`.
- `swarmbox <command>` runs a command in the box and returns its exit status; `--plain` skips tmux.
- Creation settings in one host file, compared on every entry by a fingerprint; variables are passed by name at creation and never written to disk.
- Nested Podman, always on, with the host connection (`podman -c`) and a short-symlink fallback for long socket paths.
- A web terminal (ttyd and tmux) on `127.0.0.1`, supervised inside the box; optional remote access with Cloudflare Tunnel and Access (`swarmbox remote setup|status|off|token`),
  with the credentials and the connector on the host.
- Chrome DevTools MCP with Chromium in the image, written to the MCP configuration of the agents.
- `swarmbox update [--to TAG]` refreshes the script from the new image (never by an older one) and uses an exact local tag, so a later `reset` works offline and a rollback is one command.
- No telemetry; logs stay on your machine.
- XDG-aware paths on the host and in the box.
- `LICENSE` (Apache-2.0), `THIRD_PARTY_NOTICES.md`, `CONTRIBUTING.md`, `SECURITY.md`, `CODE_OF_CONDUCT.md`, a CI workflow and a signed multi-arch release workflow.

### Known limits

macOS with a real Podman machine, Podman older than 4.3, a host user other than UID 1000 and the real Cloudflare setup are not verified. A container shares the host kernel:
see [SECURITY.md](SECURITY.md) and [docs/microvm.md](docs/microvm.md).

## [2.0.0-beta.2] - 2026-11-11

Second prerelease of 2.0.0, tagged `2.0.0-beta.2` only. Install it with `sh install.sh --version 2.0.0-beta.2`, or move from a
beta.1 box with `swarmbox update --to 2.0.0-beta.2`. Changes since beta.1:

- Fixed: with `BROWSER_URL` set, the Chrome DevTools MCP now attaches to that browser. `swarmbox-mcp` read a variable the host never
  passes (`BROWSER_URL`) instead of `SWARMBOX_BROWSER_URL`, so the generated MCP file kept the headless Chromium of the box.
- The web terminal treats Option as Meta on a Mac, so Option+1..9 and Option+N change and open tmux windows (`macOptionIsMeta=false`
  in `web-terminal.conf` brings the special characters back).
- The `tmux` status bar stays visible in the browser, so every window is listed.
- macOS test and CI fixes (macos-15 runner, tests run one by one).

## [2.0.0-beta.1] - 2026-11-11

First public prerelease of 2.0.0, for testing before the final release. The image is tagged `2.0.0-beta.1` only (never `2.0` or
`latest`) and the GitHub release is marked as a prerelease. Install it with `sh install.sh --version 2.0.0-beta.1`;
`swarmbox update` follows the `2.0` series, which exists only once 2.0.0 is out, so until then move between betas with
`swarmbox update --to TAG`. The feature list is the one of 2.0.0 below. Changes while preparing it: the base image is
`node:24-trixie-slim` (Debian 13) with Podman 5.4; `criu` and its `python3-protobuf` are removed from the image; the Go
standard library findings that Debian 13 has not fixed yet are listed, with the reasons, in `.grype.yaml`.
